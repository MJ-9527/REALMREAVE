# 规划同移 + 出生点分散 + 取消小兵永久死亡

## 1. Summary

本轮改动三件事：

1. **行动方式**：把「逐个玩家限时行动」改为「同一张图上所有存活玩家先各自规划 1-3 步路径（10 秒），再按步同时移动」。任一步走到同一节点即相遇并停下结算，结算完继续走剩余步数。
2. **出生点**：4 个出生点两两**无直接连线**、BFS 距离 ≥2，且尽量分布在地图四个象限；出口优先级下调为「离最近出生点 3-5 步」。
3. **小兵惩罚**：取消小兵永久死亡。战后阵亡小兵全部存活；怪物战失败只退回上一节点，不扣兵、不扣物资；PvP 战败仍直接出局。

用户已确认的决策（见第 4 节）全部按此执行，不再二次选择。

#### `runMoveStep` 执行细节（决定实现顺序）

1. `const T = G.turn; if (!T || T.phase !== 'move' || T.busy) return;` 先 `T.busy = true`。
2. **移动**：按 `T.order` 遍历，条件 `p.alive && p.mapNodeId != null && p.ap > 0 && plans[p.id] && plans[p.id][T.step] != null`：
   - 目标节点必须存在且是当前节点的邻居，否则清空该玩家剩余计划并跳过。
   - `p.prevNodeId = p.mapNodeId; p.mapNodeId = target; p.ap--; revealAround(...)`；记录 `moved.push(p)`。
   - `ap` 归零的玩家 **在本步移动后**立即 `forceSettle(p)` 并清空计划。
   - 全部改完位置后统一 `render()` 一次（视觉上「同时移动」）。
3. **碰撞收集**：对 `moved` + 本步原地未动的同图玩家按 `mapNodeId` 分组；同节点 ≥2 人时按 `T.order` 顺序两两入队 `{ type: 'pvp', a, b }`。
4. **到达事件**：对 `moved` 中仍存活、仍在原节点的玩家入队 `{ type: 'arrive', p }`（出口 → `extractPlayer` + 清空计划；怪物点 → `fightMonster`；其余 → `lootNode`）。
5. 队列交给 `processStepEvents`。
6. `done()` 内：`T.step++`；若 `T.step < T.maxLen` → `setTimeout(runMoveStep, MOVE_STEP_MS)`；否则 `finishMovePhase()`。

#### `processStepEvents` 事件规则

- `pvp`：两端都在同图同节点才结算。
  - 含人类 → `G.phase = 'encounter'`，走现有 `encounter(human, foe)` 的 5 秒决策 + 10 秒布阵；结束后回调继续队列。
  - 纯 AI → `pvpBattle` + `resolvePvp` 立即结算（沿用现有逻辑）；输家 `alive=false` 并清空计划。
  - 有人避战并退回 `prevNodeId` 时，清空其剩余计划。
- `arrive`：
  - `exit` → `extractPlayer(p)`、清空计划。
  - `monster`（人类）→ `fightMonster` 打完再继续队列：胜 → 保留剩余路径；败/撤 → 清空剩余路径。
  - `monster`（AI）→ `runBattle` 即时结算：胜 → `lootNode`；败 → 退回 `prevNodeId` 并清空计划（**不再扣兵**）。
  - 其他 → `lootNode`。
- 事件处理期间 `T.busy` 保持 `true`，UI 显示「本步结算中…」。

### 3.5 `prototype/js/map.js` — 出生点四周分散、互不相连

重写 [pickSpawnSet](file:///d:/github/game/prototype/js/map.js#L159-L190)：

1. 预算 4 个出生点的两两 BFS 距离表（对每个外圈节点调 `bfsDistances(all, id)`）。
2. 采样 500 次「外圈随机取 4 个」；候选必须满足：
   - 任意两两 **无直接边**（`!a.neighbors.includes(b.id)`）；
   - 任意两两 BFS 距离 **≥2**。
3. 计分：`象限覆盖数 * 10000 + 最小两两 BFS 距离 * 100 + 最小欧氏距离`，取最高分（象限按 `n.x/n.y` 相对 `CENTER` 划分 4 块，推动「分布在地图四周」）。
4. 500 次内无合法解时兜底：按「每个象限各取 1 个、最大化两两 BFS 距离」贪心选择；仍不足 4 个就补当前最小冲突节点（保证功能可用）。

出口选择（[generateMap](file:///d:/github/game/prototype/js/map.js#L246-L278)）：

- 阈值由 `6→5→4→3` 改为 `5→4→3`，即优先「离所有出生点 ≥5 步」，不可行时退到 4、3，最后取最大值；**不再要求 5-9 步**。
- 两个出口仍彼此拉开（欧氏 >170 优先），且不与出生点重合。
- `others` 排除出生点与已选出口。

`ensureBranching` 增加可选 `avoidIds` 参数（[L123-L130](file:///d:/github/game/prototype/js/map.js#L123-L130)）：

- 调用改为 `ensureBranching(n, outer, new Set([...spawns, ...exits].map(x => x.id)))`；
- 候选过滤加上 `!avoidIds.has(n.id)`，避免补边时把两个出生点或出生点-出口直接连起来；
- 补边后保持「出生点两两 BFS ≥2」不变（因为补边目标被排除）。

## 4. Assumptions & Decisions

| 决策 | 结论 |
| --- | --- |
| 相遇判定 | 任一步走到同一节点即相遇并停下，剩余步数在结算后继续；**只判定节点重合**，交叉换边不算相遇 |
| 路径中途事件 | 先停下结算（PvP 优先于怪物/物资），打完后若仍在原路径且位置未变则继续走剩余步数；被击退/撤退/出局则清空剩余路径 |
| 小兵死亡 | 战后全部复活，无永久损失；怪物战失败不扣兵、不扣物资，仅退回上一节点；PvP 战败仍直接出局 |
| 出生点 | 4 个出生点两两无直接连线、BFS ≥2、尽量覆盖 4 个象限；出口放宽为离最近出生点 3-5 步 |
| 规划操作 | 地图上按住拖拽画路径，松手后按钮确认；10 秒超时自动按当前预览确认，未规划则原地不动 |
| 规划上限 | 每周期最多 3 步，且不超过剩余 AP |
| AI 规划 | 用现有 `aiNodeScore` 贪心预计算 3 步（对人类不可见）；AI 避战判断保留在单步结算时 |
| 周期循环 | 一个规划周期走完，若仍有人 `alive && mapNodeId != null && ap > 0`，立即进入下一规划周期（cycle+1）；全部离场则 `checkRoundEnd()` |
| 计时器 | `MAP` 规划阶段真实倒计时 10 秒；同步移动阶段不计时，按 320ms/步播放 |
| 战斗前流程 | 5 秒决策 + 10 秒布阵保持不变；决策期间不计规划时间（规划阶段本身已结束） |
