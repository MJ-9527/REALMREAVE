# 战斗同时结算 · 5 秒决策 · 10 秒布阵 · 出生点与出口 改造计划

## 一、需求与已确认决策

用户需求：

1. 战斗要“全部兵种同时战斗输出”；进入战斗先给 5 秒决定“战斗还是逃跑”，再给 10 秒布置阵型。
2. 所有玩家出生点各不相同；出口数量随该地图本轮玩家数变化：4 人两出口，4 人以下 1 出口。

问答确认结果（用户已选）：

| 决策点 | 结论 |
| --- | --- |
| 同时输出 | **每轮全体同时出手**：保留射程与移动，同轮内所有单位的攻击一起结算，不分先后 |
| 5 秒决策 | **所有战斗（含怪物点）都给 5 秒**；超时默认**开战** |
| 10 秒布阵 | **手动点击/拖拽布阵**；超时按当前布局开战 |
| 出生点 | **每轮随机、同一地图内不重复**并尽量拉开距离 |
| 出口数量 | **每轮按该图实际存活人数**确定：4 人 = 2 出口，≤3 人 = 1 出口 |
| 同归于尽 | 互相击杀时**速度高者存活**，速度相同比攻击力，仍相同则双方阵亡 |

## 三、实现方案

### 3.1 战斗改为“每轮全体同时出手”（battle.js）

**目标**：保留射程与移动；一轮内先全体移动，再全体出手，所有伤害在轮末一次性生效。

**改造 `runBattle`**：把 `while` 循环体内的“逐单位行动”替换为 `resolveRound(all, round, events, textLog)`，其余初始化和胜负判定不变。

新增 `resolveRound` 流程：

1. **定身结算**：开局对本轮 `stunned > 0` 的单位 `stunned--`，加入 `stunSkip` 集合并 emit `{t:'stun'}`，这些单位本轮不出手。
2. **移动阶段（仍逐个移动，避免重叠）**：存活且未定身的单位按 `(speed desc, range asc)` 排序；对每个单位重新 `pickTarget`，若 `cheb > range` 则用 `stepToward` 最多移动 `moveRangeOf(unit)` 步；发生过移动的单位各 emit 一次 `frame`。
3. **出手意图（基于移动后的状态）**：对每个存活未定身单位重新 `pickTarget`；
   - 英雄满足 `shouldCastSkill` → 记为技能意图（龙族 AoE / 精灵定身）；
   - `cheb <= range` → 记为普通攻击意图。
   意图只记录 `{attacker, target/skill}`，**不扣血**。
4. **伤害计算（新函数 `computeHit(attacker, target, mult)`）**：把 `doAttack` 中的英雄倍率（战士首击 ×1.8、刺客斩杀 ×1.8、狂战残血 ×1.5、弓手 ×1.5）、`damageOf`、克制系数抽出来，返回 `{attacker, target, dmg, counter, skill?}`，不改状态。
   - 骑士减伤：同一轮只减免一次，作用于**本轮承受伤害最高的一次**（确定顺序：按攻击者 speed 降序，取第一条命中的最大伤害）。
   - 龙族 `castSkill` 改写为返回 AoE 命中列表（范围内每个敌人一条 hit），精灵改写为“定身 + 不造成伤害”，命中列表统一进入第 5 步。
5. **统一结算**：
   - 先记录 `beforeHp`；按目标汇总所有 hit 的伤害，一次性扣减 `hp`；
   - 收集本轮新死亡单位并标记 `alive=false, hp=0`；
   - 同归于尽判定 `resolveMutualKills`：对每个本轮死亡单位，找出同样本轮死亡、且曾攻击它的单位；双方中 **speed 高者复活为 1 HP**（speed 相同比 `atk`，仍相同则双方保持阵亡）。按 speed 降序处理，每个单位最多复活一次；
   - 按 speed 降序 emit 全部 `{t:'attack', ..., simul:true}` 事件（含 `died` 标记），最后 emit 一次 `frame`。
6. 返回双方是否仍有存活，任一方清空则 `runBattle` 结束循环（仍保留 `MAX_ROUND = 12` 与百分比平局判定）。

**回放适配（game.js `playBattle`）**：副标题改为“全体同时出手 · 最多 12 回合”；`delayOf` 对 `ev.simul` 的攻击事件用 `180 / speed` 毫秒，避免一轮十几条攻击回放拖太久；其余动画、跳过、结算逻辑不变。

### 3.2 进入战斗 5 秒决策（game.js）

新增常量 `DECIDE_SECONDS = 5`，新增 `battleDecision(cfg)`：
- `cfg = { title, sub, sideCardsHtml, onFight, onFlee, fightText, fleeText }`；
- 设置 `G.phase='battle'` 并 `clearTurnTimer()`（决策期间暂停 10 秒回合倒计时）；
- overlay 显示双方卡片、倒计时 `5.0s` + 进度条、“开战”“撤退”按钮；
- 内部 100ms `setInterval`，归零时自动执行 `onFight()`（默认开战）；两个按钮分别执行 `onFight/onFlee` 并清计时；
- 新增 `decisionFight()` / `decisionFlee()` 全局函数供按钮调用，防止重复触发（`G.decision.done`）。

接入点：
- `encounter(human, foe)`：保留现有“AI 判断实力悬殊则避战”逻辑；之后改为调用 `battleDecision`，`onFight → startEncounterBattle()`，`onFlee → fleeEncounter()`（现有惩罚不变：丢一半物资、退回上一节点、结束回合）。
- `fightMonster(p, node, onDone)`：人类分支在 `playBattle` 前插入 `battleDecision`，`onFight` 进入布阵/战斗；`onFlee` 执行新增 `fleeMonster(p)`：丢一半物资、退回 `prevNodeId`、记录战报、`endCurrentTurn()`。AI 分支不变。

### 3.3 10 秒手动布阵（game.js + render.js + style.css）

新增常量 `FORMATION_SECONDS = 10`，新增 `openFormation(cfg)`：
- `cfg = { title, sub, teamA, teamB, labelA, labelB, onReady(teamA, teamB) }`；
- 初始布局：队伍已由 `teamOf` / `makeTeam` 用 `smartFormation` 摆好，直接以此为初始阵型；
- 设置 `G.phase='battle'`、`clearTurnTimer()`，overlay 内放 `formationCanvas`（`BATTLE_W × BATTLE_H`）+ 右侧单位名单 + 10 秒倒计时/进度条 + “自动阵型”“开始战斗”按钮；
- 交互（canvas pointer 事件）：
  - `pointerdown` 命中己方（side A）单位 → 选中并开始拖拽；
  - `pointermove` 更新悬停格高亮；
  - `pointerup` 落在己方部署区（x=0,1）：空格 → 移动；被己方单位占用 → **交换位置**；落在区外 → 恢复原位。
  - 未拖动时也可“点单位 → 点空格”完成摆放（同一次 pointer 流程兼容）。
- “自动阵型”按钮：对 `teamA` 重新执行 `smartFormation('A', teamA)` + `dedupePositions('A', teamA)`。
- 倒计时归零或点“开始战斗” → `finishFormation()`：清计时、`hideOverlay()`、`onReady(teamA, teamB)`；
- 双方单位在布阵界面均可见（敌方按默认阵型站位），便于针对性布阵。

渲染：在 render.js 新增 `drawFormation(ctx, teamA, teamB, opts)`，复用 `drawBattle` 的格子/部署区/中缝绘制，额外绘制：
- 可放置格高亮（`opts.hoverCell`）；
- 选中/拖拽单位外圈（复用 `drawUnit` 的 `opts.selUid`，在 `drawUnit` 中新增选中金圈分支）。

样式：在 style.css 战斗区块后追加 `.formation-wrap`（复用 `battle-wrap`）、`.formation-ctrl`、`.form-hint` 等少量样式。

接入点：
- `pvpBattle(a, b, env, cb)`：人类参与时，创建 `teamA/teamB` 后先 `openFormation`，再 `playBattle`（传入布阵后的 teamA/teamB）；AI 对 AI 分支保持同步 `runBattle`。
- `fightMonster` 人类分支：`battleDecision` → `openFormation` → `playBattle`。
- 战斗结束回调保持现状：PvP 结束本回合/出局观战；怪物点胜利后回探索并 `afterHumanStep()`。

### 3.4 出生点每轮随机不重复、出口按人数开放（map.js + game.js）

**map.js 生成阶段**：
- 新增 `pickSpawns(outer, all)`：从外圈节点贪心选 4 个，每次选“与已选出生点最小距离最大”的节点（同分随机），保证彼此尽量分散；写入 `map.startIds`（全部标记为 `start` 类型）。
- 出口候选固定生成 **2 个**，条件是“对**每一个**出生点的 BFS 距离都 ≥ 6”，并按与所有出生点的最小距离降序排序；不足时依次降到 ≥5、≥4，再不足则取距离最大的外圈节点。两个候选之间距离 > 170px，并都执行 `ensureBranching`。
- 地图对象改为：
  ```js
  { env, nodes, byId, rings, startIds: [...], exitCandidates: [...], exitIds: [] }
  ```
  去掉单一 `startId`（`game.js` 中 3 处引用同步替换）。
- 生成时 `setType` 只在生成阶段使用；新增全局 `setNodeType(n, type)` 供每轮切换使用。

**game.js 每轮开始（`startRound`）**：
- 刷新物资后，按 `mapId` 分组存活玩家：`const group = 该图存活玩家`；
- 对每张有玩家的地图执行 `applyMapRound(map, group.length)`：
  - `const openCount = group.length >= 4 ? 2 : 1`；
  - `map.exitIds = map.exitCandidates.slice(0, openCount)`；
  - 遍历 `exitCandidates`：开放者 `type='exit'`（清空 stock），未开放者 `type='normal'` 并生成正常物资；
- 出生分配：`const spawns = shuffle(map.startIds).slice(0, group.length)`，逐人分配（同一图内绝不重复），设置 `mapNodeId / prevNodeId`，并 `revealAround(map, spawnId)`；
- 顺序必须是：`refreshMapStock` → `applyMapRound` → 分配出生点 → `fastForwardOtherMaps` / `initMapTurns`，确保 AI 推演看到的出口类型已按人数更新。

**展示**：同一地图的多个出生点都显示“入”图标（玩家能提前看到全部出生点，但每轮实际起点随机），出口按当前开放数量显示“出”图标，未开放的候选节点显示为普通节点。

## 四、假设与决策

1. 同时出手仍保留射程与移动，远程需先进入射程才能打（用户已确认）。
2. 5 秒决策覆盖 PvP 与怪物点，超时默认开战；AI 对 AI 的战斗不弹窗、不等待。
3. 逃跑惩罚统一：丢一半物资、退回上一节点、结束本回合（怪物点沿用同一规则）。
4. 布阵只允许放在己方两列（A: x=0,1），落点被己方单位占用则交换位置；飘在区外则还原。
5. 布阵界面双方单位可见；超时按当前布局直接开战，不会出现“未摆放单位”。
6. 每轮为每张地图单独判定出口数量；本轮无人选择的地图不做切换（无人可见）。
7. 出生点每轮重新随机（同一地图内不重复），不跨轮记忆。
8. 战斗回合上限保持 12；平局仍按剩余血量百分比判定。
