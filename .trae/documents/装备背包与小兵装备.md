# 装备背包 · 小兵装备 · 物资管理改造

## 一、摘要

本次改造解决三件事：

1. **看得见物资**：背包与商店出售区都按「名称 + 品质」显示，可逐件指定出售；当前可合成配方所需的材料自动标记为「锁」不可出售，支付时也优先避开它们，避免误卖。
2. **装备有去处**：新增**装备背包**（不限容量）。商店购买、配方合成、节点掉落得到的装备先入包，玩家在补给窗口手动穿戴/替换/卸下/出售，不再"更好就自动穿、更差就自动 5 折卖掉"。
3. **小兵能用装备**：每名小兵 1 个装备槽（仅武器 / 护甲，饰品不可），加成计入战斗数值，让小兵成长不再只有兵种等级一条线。

套装不在本次实现范围，但槽位与背包结构天然支持后续给装备加 `set` 字段做套装统计。

## 二、现状分析

- **物资**：`p.materials` 是 `{n, q}` 数组；侧栏 `renderSide()` 只按品质统计数量（game.js L773-778），看不到名称。商店出售区同样只按品质分组（L2073-2080），`sellMaterial(qKey)` 会卖掉该品质的**第一件**（L2172-2183），玩家无法指定卖哪件——这是"容易卖掉需要的东西"的直接原因。
- **支付**：`payFrom()`（L1884-1898）按价值从低到高把材料放进"保留列表"，等于**优先花掉高价值材料**，完全不考虑配方需求。
- **装备获取**：三条途径都会自动处理——节点掉落 `grantEquip()`（L1017-1034）、商店 `buyEquip()`（L2107-2132）、合成 `craftInto()`（L1993-2006）：空槽直接穿、更好则替换并把旧装备 5 折回收、更差则直接 5 折回收。玩家没有任何选择权，也不存在装备背包。
- **装备槽**：英雄只有 3 槽 `p.equips = [weapon, armor, trinket]`，`equipBonus()`（units.js L106-116）只作用于英雄（`heroToBattleUnit`）。
- **小兵**：`makeSoldier()`（units.js L9-29）无装备字段；战斗出场 `cloneSoldierForBattle()`（game.js L1096-1099）只按 `soldierStats(cls, tier, level)` 计算；升级只有商店随机一个兵种 +25%/级（L2148-2170）。
- **商店弹层**：`renderShop()`（L2008-2103）三列商品 + 出售区 + 配方区，弹层本身可滚动（style.css L335-342）。

## 三、改动方案

### 1. `prototype/js/units.js`

- `makePlayer()` 增加 `equipBag: []`（装备背包，不限容量）。
- `makeSoldier()` 增加 `equip: null`（小兵唯一装备槽）。
- `playerValue()` 追加背包内装备与士兵已穿装备的 50% 估值，保持"身家"统计一致：

```js
for (const e of p.equipBag) v += Math.round(equipPrice(e) * 0.5);
for (const s of p.soldiers) if (s.equip) v += Math.round(equipPrice(s.equip) * 0.5);
```

- `equipBonus(equips)` 不改逻辑，作为英雄与小兵的统一加成入口（士兵传 `[s.equip]`）。

### 2. `prototype/js/game.js` —— 装备统一入包

- `grantEquip(p, qKey)`：随机槽位生成装备后 **`p.equipBag.push(eq)`**，返回值改为 `{ eq }`，不再自动穿/卖。
- `lootNode()`（L1002-1011）掉落文案改为「掉落装备 X（已放入装备背包）」。
- `buyEquip(i)`（L2107-2132）：支付成功后 `me.equipBag.push(it.eq)`，删除全部新旧对比与折价回收分支；日志「购入 X（已放入装备背包）」。
- `craftInto()`（L1993-2006）：`takeMaterial` 后生成装备并 `p.equipBag.push(eq)`，返回 `{ eq }`；`doCraft()` 去掉 `res.sold` 分支，日志「合成 X（已放入装备背包）」。
- `renderShop()` 装备卡片（L2013-2025）：删除 `better` 判断，文案固定为「购入后进入装备背包」。

### 3. 装备管理交互（仅补给窗口 `G.phase === 'shop'`）

新增状态：`G.equipPick`（背包中选中装备的 `uid` 或 `null`），`showShop()` 开局置 `null`。

新增函数：

- `findBagItem(me, uid)`：从背包取装备。
- `pickEquipBag(uid)`：点选/取消选中背包装备（选中项高亮），`renderShop()`。
- `equipHeroSlot(idx)`：选中装备 `slot` 与 `idx` 对应槽位匹配时穿上；原装备回包；不匹配则日志「槽位不符」。
- `equipSoldierSlot(i)`：选中装备为 `trinket` 时拒绝并日志「小兵不能装备饰品」；武器/护甲则替换该士兵 `equip`，原装备回包。
- `unequipSlot(kind, idx)`：`hero` / `soldier` 卸下回包。
- `sellEquipFromBag(uid)`：背包内装备按 `Math.round(equipPrice(eq) * 0.5)` 换物资点并移出背包（已穿戴的装备需先卸下）。
- 每个动作结尾统一 `renderShop(); renderSide();`。

**商店 UI**：`renderEquipPanel(me)` 新面板，放在「出售物资」上方：

- 上半区「英雄槽位」3 个按钮 + 「小兵槽位」5 个按钮（显示兵名 / `Lv` / 当前装备或「空」），选中背包装备时目标加高亮类 `.eq-target.armed`。
- 下半区「装备背包（N）」列表，每行：名称（品质色）+ 槽位/品质 + 加成摘要（如 `ATK +20` / `HP +60 DEF +10`）+ 「出售」按钮；行本身点选。
- 顶部提示：「先点背包装备，再点英雄槽或小兵；点已穿戴的槽位可卸下」。

### 4. 小兵装备生效

- `cloneSoldierForBattle(s)`（L1096-1099）：

```js
const st = soldierStats(s.cls, s.tier, s.level);
const b = s.equip ? equipBonus([s.equip]) : { atk: 0, hp: 0, def: 0 };
return Object.assign({}, s, {
  maxHp: st.hp + b.hp, hp: st.hp + b.hp,
  atk: st.atk + b.atk, def: st.def + b.def
});
```

- `renderSide()` 部队块（L787-792）：每个小兵格追加 `<div class="eq">${装备名 或 空}</div>`，品质色沿用 `q-${quality}`。

### 5. 物资清单与出售改造

- 新增 `groupMaterials(list)`：按 `n + '|' + q` 聚合为 `[{ n, q, count }]`，排序 = `MATERIAL_NAMES` 顺序，再按品质由高到低。
- `renderSide()` 背包块（L839-842）：改为名称化清单，每个 chip 文案 `铁锭·紫×2`，保留 `q-<quality>` 颜色类。
- 新增 `lockedMatNames(p)`：遍历 `RECIPES`，对 `craftCheck(p, r)` 不为 null 的配方，收集 `r.main` 与 `r.aux` 全部名称到 `Set`（当前可合成才锁）。
- `renderShop()` 出售区改为按名称分组 chip：`sellMaterialByName('铁锭','purple')`；名称在 `lockedMatNames` 中时 chip 加 `.locked` 且不可点击，文案追加 `锁`，`title` 提示「当前可合成配方需要，暂不可出售」；标签行说明锁定规则。
- `sellMaterialByName(name, qKey)` 取代 `sellMaterial(qKey)`：按 `n === name && q === qKey` 精确删除 1 件。
- 配方行（L2061-2071）：`rmat` 改为逐项显示「名称 拥有/需要」，缺料项标红（如 `铁锭 1/1` 正常、`皮革 2/3` 红色）。

### 6. 支付保护合成材料

`payFrom(p, amount)`（L1884-1898）改为两段式挑选"保留"材料：

1. 计算 `keep = total - amount` 与 `locked = lockedMatNames(p)`。
2. 先按价值升序保留锁定材料（放得进 `keep` 就保留）；
3. 再用未锁定材料按价值升序填满 `keep`；
4. 未保留即支付掉；余额转 `p.credit`。
5. 若本次支付确实消耗了锁定材料且 `p.isHuman`，追加日志「支付动用了合成材料：…」。

这样默认优先消耗未锁定的低价值材料，只有在物资不足时才会动配方材料。

### 7. AI 补给适配

新增 `aiEquipBag(p)`（在 `aiShop` 末尾调用，替换现有"买装备直接穿"逻辑）：

- 逐件取出背包装备：英雄对应槽为空或品质更高 → 穿上，旧件回包继续处理；
- 否则若为武器/护甲且有士兵空槽 → 给第一个空槽小兵；
- 否则 5 折换物资点。
- 加 `guard` 上限 12 次防止死循环。

### 8. `prototype/css/style.css`

新增精简样式：

- `.mat-chips` / `.chip.locked`（灰化 + 不响应点击）；
- `.eq-manage`（两行网格）、`.eq-target`、`.eq-target.armed`、`.eq-bag`（`max-height:150px; overflow-y:auto`）、`.eq-item`、`.eq-item.sel`；
- `.unit-tile .eq`（小兵装备行，10px）。

  - 6.1 局内装备：英雄 3 槽 + **小兵各 1 槽（仅武器/护甲）**；装备先入背包，补给窗口内手动穿戴/替换/卸下/出售；同件装备可随时更换、不消耗；套装加成预留。
  - 6.3 兵种等级：补充「小兵装备是第二条成长线」。
  - 6.4 轮间窗口：可做事项加「穿/换装备（含小兵）、出售多余装备」。
  - 6.6 三条获取途径：统一说明「获得后进入装备背包」。

## 四、决策与假设

- **装备管理只在补给窗口（shop）进行**；探索/战斗阶段侧栏只读展示，避免中途换装打乱战斗平衡。
- **装备背包不限容量**，不设"溢出"；重复装备的唯一去处是给士兵或 5 折出售。
- **小兵槽位仅接受武器/护甲**，无职业限制（当前装备数据无职业字段，避免改动商店/合成的生成逻辑）；饰品为英雄专属。
- **出售价格统一 5 折**（沿用现有回收口径）；已穿戴装备必须先卸下才能出售。
- **配方锁定的粒度 = 材料名称**：只要该名称出现在任一当前可合成配方中，该名称的所有品质整体锁定；不可手动解锁，避免误操作。
- **`payFrom` 只做偏好保护**：当未锁定材料不足以支付时，仍会消耗锁定材料，保证购买不被卡死。
- 套装不在本次实现；不新增套装字段，未来在 `equipBonus` 中按 `set` 统计即可。

## 五、验证步骤

1. `node --check prototype/js/units.js game.js battle.js map.js render.js` 全部通过。
2. **E2E-1 购买入包与穿戴**：进入商店，购买 1 件装备 → 断言 `me.equipBag.length === 1` 且英雄槽未自动变化；点选该装备再点对应英雄槽 → 槽位更新、背包减少；再买同槽更好装备并手动替换 → 旧件回到背包。
3. **E2E-2 小兵装备**：给一名小兵穿武器/护甲，断言 `cloneSoldierForBattle(s).atk/hp/def` 高于无装备值；尝试给士兵穿饰品被拒绝。
4. **E2E-3 出售与锁定**：构造一套可合成材料，断言对应名称 chip 带锁且点击不出售；未锁定材料点击后按名称精确减少 1 件；背包装备出售后 `credit` 增加 5 折价值。
5. **E2E-4 支付保护**：`credit = 0`、材料含配方主材与多余低品质材料，调用商店购买，断言优先消耗未锁定材料；仅在不足时才动锁定材料。
6. **回归**：规划→同步移动、PvP/怪物战、整轮进入商店的既有流程无报错；`GAME_DESIGN.md` 与实现一致。
