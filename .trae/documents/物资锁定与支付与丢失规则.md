# 物资锁定 / 纯手动支付 / 随机丢失 改造计划

## 一、需求摘要

1. **金色及以上物资默认锁定**，白 / 蓝 / 紫不锁；锁定物资点击「锁」图标即可解锁（解锁后可出售）。
2. **材料不再自动抵扣货款**：商店只能用「物资点」支付，材料必须先手动出售换成物资点。
3. **失去物资改为纯随机**：不再固定丢品质最高的那些，随机取一半（向上取整）。

用户已确认的口径：
- 配方锁**保留但只锁主材**（不再锁辅材），与品质锁并存。
- 支付：**材料一律不自动花**。
- 丢失：**纯随机丢一半（按件数，向上取整）**。

## 二、现状分析

### 2.1 锁定与出售（game.js）

- `lockedMatNames(p)`（L2034-2042）：遍历 `RECIPES`，只要 `craftCheck` 通过，就把该配方的 **主材 + 全部辅材名称** 加锁，粒度是「名称」。
- `renderShop()`（L2115-2123）：按名称锁结果给 chip 加 `.locked` 类与「锁」标，**不可点击**。
- `sellMaterialByName(name, qKey)`（L2260-2272）：名称被锁则直接 return。
- `payFrom(p, amount)`（L1883-1912）：`credit + 材料价值` 一起当预算，先保锁定材料，再用未锁定材料凑，最后找零 —— 这就是「好物资被自动消费」的根因。
- `budgetOf(p)`（L1969）= `p.credit + materialsValue(p.materials)`，被商店所有购买按钮与 AI 复用。

### 2.2 物资丢失（game.js）

- `dropHalfMaterials(p)`（L1026-1034）：按价值降序排序后取前 `ceil(n/2)` 件，**已经是确定性丢最贵的**，共 8 处调用（避战、强制结算、PVP、撤退、避开怪物、AI 避战等）。

### 2.3 数据结构（units.js）

- `makePlayer()` 有 `materials` / `credit` / `equips` / `equipBag`，**没有「已解锁材料」字段**。

### 2.4 文档

- `GAME_DESIGN.md` v0.5：L228 / L244（撤退丢一半）、L353-360（PVP 战果）、L550（装备入包）、L557-562（逐件出售 + 配方锁定 + 支付优先扣未锁定）、L660-677（第 9 节已确认）。
- `prototype/js/data.js` 顶部版本注释为 v0.5。

## 三、改动方案

### 3.1 `prototype/js/units.js`

`makePlayer()` 在 `equipBag: []` 之后新增：

```js
matUnlocked: [],        // 玩家手动解锁的材料「名称|品质」键
```

### 3.2 `prototype/js/game.js`

#### ① 锁定模型：实例级 + 双来源（替换 `lockedMatNames`）

删除 `lockedMatNames(p)`，新增两个函数（放在原位置附近，`craftCheck` 之后）：

```js
/** 品质锁：金 / 红 / 彩 默认锁定 */
function isQualityLocked(qKey) {
  return QINDEX[qKey] >= QINDEX.gold;
}

/** 当前可合成配方会消耗的那件主材实例（只锁主材，不锁辅材） */
function recipeMainMats(p) {
  const set = new Set();
  for (const r of RECIPES) {
    const chk = craftCheck(p, r);
    if (chk) set.add(chk.main);
  }
  return set;
}

/** 实际锁定的材料实例：品质锁 ∪ 配方主材锁，去掉玩家手动解锁的「名称|品质」 */
function lockedMats(p) {
  const set = new Set();
  for (const m of p.materials) if (isQualityLocked(m.q)) set.add(m);
  for (const m of recipeMainMats(p)) set.add(m);
  const un = new Set(p.matUnlocked || []);
  for (const m of [...set]) {
    if (un.has(m.n + '|' + m.q)) set.delete(m);
  }
  return set;
}
```

说明：用**实例引用**而非名称，这样「有 3 件紫铁锭、其中 1 件是配方主材」时，仍可卖掉另外 2 件，只有被配方盯上的那 1 件上锁。

#### ② 解锁交互

```js
/** 点击锁标：解锁该「名称 + 品质」的全部材料 */
function unlockMaterial(name, qKey) {
  const me = G.me;
  if (!me) return;
  const key = name + '|' + qKey;
  me.matUnlocked = me.matUnlocked || [];
  if (!me.matUnlocked.includes(key)) me.matUnlocked.push(key);
  log(`解锁 ${name}（${QMAP[qKey].name}），现在可以出售`);
  renderShop();
  renderSide();
}
```

#### ③ 商店出售区重绘（`renderShop()` L2115-2123）

- 用 `lockedMats(me)` 统计每组（`groupMaterials` 产物）的锁定件数 `lockCount`：
  `lockCount = me.materials.filter(m => m.n === g.n && m.q === g.q && lockedSet.has(m)).length`
- `free = g.count - lockCount`
  - `free > 0` → chip 可点击出售 1 件（`onclick="sellMaterialByName('${g.n}','${g.q}')"`）。
  - `free === 0` → chip 加 `.locked` 类，不可出售，`title` 说明「金色及以上默认锁定，点「锁」标解锁 / 配方主材」。
- `lockCount > 0` 时追加可点击锁标：
  `<span class="lock" onclick="event.stopPropagation();unlockMaterial('${g.n}','${g.q}')" title="点击解锁">锁${lockCount}</span>`
- 出售区提示文案改为：
  「出售物资 · 7 折回收（点一次卖 1 件）　·　金色及以上默认锁定，配方主材也锁定；点「锁」标解锁」

#### ④ 支付改为纯物资点（`payFrom`）

```js
/** 支付只能使用物资点：材料必须由玩家手动出售 */
function payFrom(p, amount) {
  if (p.credit < amount) return false;
  p.credit -= amount;
  return true;
}
```

- `budgetOf(p)` 改为 `return p.credit;`
- 商店副标题（L2128）改为：
  「可用物资点 <b>${budget}</b>　·　材料不会自动抵扣，需在下方先出售」
- `sellMaterialByName()` 内部判锁改为：

```js
const lockedSet = lockedMats(me);
const i = me.materials.findIndex(m => m.n === name && m.q === qKey && !lockedSet.has(m));
if (i < 0) return;
```

#### ⑤ AI 适配（`aiShop`）

新增 `aiEnsureCredit(p, need)`：按品质升序卖材料（跳过 `recipeMainMats(p)` 里的实例）直到 `p.credit >= need`；AI 不受品质锁限制（无手滑风险，保持战力成长节奏）。

`aiShop` 中三处购买前把
`if (budgetOf(p) < price) ...` 改为 `if (!aiEnsureCredit(p, price)) ...`（买兵处 `break`，升级 / 买装备处 `continue`），随后照旧 `payFrom`。

#### ⑥ 丢失改为随机（`dropHalfMaterials`）

```js
function dropHalfMaterials(p) {
  const list = shuffle(p.materials);
  const n = Math.ceil(list.length / 2);
  const lost = list.slice(0, n);
  const lostSet = new Set(lost);
  p.materials = p.materials.filter(m => !lostSet.has(m));
  return lost;
}
```

（`shuffle` 已存在于 data.js；用实例 Set 过滤，避免同名同品质重复件被误删。）

#### ⑦ 侧栏展示（`renderSide()` L774-776）

背包 chip 追加只读锁标（不绑定点击，提示「补给窗口内可解锁」）：
`<span class="lock ro">锁N</span>`，`N` 为该名称+品质的锁定件数，`N` 为 0 时不显示。

## 四、假设与决策

- 锁定是**实例级**的：同名同品质有多件时，只有被品质锁覆盖的全部件、或配方点名的那一件不可卖；其余可卖。
- 解锁粒度是「名称 + 品质」并**持久保存在玩家身上**：同一 key 后续再获得的材料默认也是解锁状态。
- 解锁只对玩家可见的出售/支付生效；AI 始终按「跳过配方主材、品质升序」卖材料，不写 `matUnlocked`。
- 需要「重新上锁」的场景未提出需求，本次不做。
- `materialsValue` 仍用于身家 / 结算统计，只是不再参与商店预算。
